# mail-sieve 1.2

Раскладка входящей почты по папкам в Carbonio Mail через серверный Sieve-скрипт
(атрибут `zimbraAdminSieveScriptAfter`). Проверялось на Carbonio 26.9.0.

Общая папка «Рассылки» работает по заголовкам письма, поэтому PMG и rspamd для неё не нужны.
Остальные письма (Redmine, письма с пометкой антиспама и т.д.) раскладываются по правилам из `rules.conf`.

## Как это работает

Серверный Sieve не умеет подключать внешние файлы, поэтому `apply.sh` собирает один скрипт из
`rules.conf` и `whitelist.txt` и записывает его в атрибут каждого домена. Заодно он создаёт
нужные папки в ящиках.

Порядок проверок в готовом скрипте:

1. Правила из `rules.conf`. Первое подошедшее кладёт письмо в папку и завершает обработку,
   белый список на него не действует.
2. Белый список. Письмо остаётся во «Входящих» и до общего правила не доходит.
3. Общее правило: если есть `List-Unsubscribe`, `List-Id` или `Precedence: bulk|list|junk`,
   письмо уходит в `NEWS_FOLDER`.

Скрипт стоит в позиции After и выполняется после личных фильтров пользователя (см. ниже).

## Требования

- Carbonio Mail, пользователь `zextras`, команды `carbonio prov` и `zmmailbox`
- bash 4.4 или новее, `flock` и `runuser` из util-linux
- `zimbraAdminSieveScriptAfter` в 26.9.0 доступен на уровнях domain, cos и account, на
  globalConfig его нет. Поэтому скрипт записывается на каждый домен.

## Установка

```
tar xzf mail-sieve-1.2.tar.gz
cd mail-sieve
sudo ./install.sh
```

Установщик копирует файлы в `/opt/mail-sieve`, создаёт конфиги (существующие не трогает),
добавляет cron на 03:15 и logrotate. Без cron: `./install.sh --no-cron`.

Первый запуск:

```
su - zextras
cd /opt/mail-sieve
nano mail-sieve.conf rules.conf whitelist.txt
./apply.sh --dry-run
./apply.sh
```

## Настройка

### mail-sieve.conf

Читается как bash-скрипт.

```
NEWS_FOLDER="Рассылки"
EXTRA_FOLDERS=("Антиспам" "Задачи" "redmine/infra")
DOMAINS=""
EXCLUDE_REGEX='^(galsync|spam\.|ham\.|virus-quarantine\.)'
```

`NEWS_FOLDER` принимает одно имя: общее правило рассылок кладёт письмо ровно в одну папку.
Если нужно раскладывать рассылки по нескольким папкам, добавляйте правила в `rules.conf`
(по отправителю, домену или заголовку), они обрабатываются раньше общего.

`EXTRA_FOLDERS` это массив папок, которые создаются в каждом ящике независимо от правил.
Значения в кавычках через пробел, вложенные папки через слэш. Папки, упомянутые в `rules.conf`
и `NEWS_FOLDER`, создаются сами, добавлять их сюда не нужно.

`DOMAINS` задаёт домены через пробел. Пустое значение означает все домены сервера.

`EXCLUDE_REGEX` исключает ящики по адресу, но только при создании папок. Системные ящики
(`zimbraIsSystemAccount=TRUE`) пропускаются автоматически.

### rules.conf

Поля разделяются точкой с запятой, строки с `#` пропускаются.

```
header-exists;ЗАГОЛОВОК;ПАПКА
header-contains;ЗАГОЛОВОК;ТЕКСТ;ПАПКА
subject-contains;ТЕКСТ;ПАПКА
from-domain;ДОМЕН;ПАПКА
from-address;АДРЕС;ПАПКА
```

Пример:

```
header-exists;X-Redmine-Project;redmine
header-contains;X-Mailer;Redmine;redmine/infra
subject-contains;[Антиспам];Антиспам
from-domain;github.com;GitHub
```

Замечания:

- Регистр в именах папок имеет значение. Если у пользователей уже есть `redmine`, пишите `redmine`,
  иначе рядом появится вторая папка `Redmine`.
- Системные папки называются по-английски: `Inbox`, `Sent`, `Drafts`, `Trash`, `Junk`.
  Папка «Спам» в интерфейсе это `Junk`. Если написать `Спам`, будет создана новая папка.
- Порядок строк важен, срабатывает первое подошедшее правило.
- Для `from-domain` поддомены нужно перечислять отдельно.
- Имена заголовков берите из оригинала письма. Значения сравниваются без учёта регистра.
- Папка `Junk` чистится автоматически по сроку `zimbraMailSpamLifetime`. Для писем, которые
  нужно хранить, заведите отдельную папку.

### whitelist.txt

Один адрес или `@домен` на строку. Поддомены добавляются отдельно.

```
bank@example.ru
@mycompany.ru
```

Белый список защищает только от общего правила рассылок. Правила из `rules.conf` он не отменяет.

## Команды

```
./apply.sh --dry-run        показать готовый Sieve, ничего не менять
./apply.sh                  создать папки и загрузить скрипт на домены
./apply.sh --no-folders     только обновить скрипт
FORCE=1 ./apply.sh          перезаписать на домене чужой Sieve-скрипт
```

Проверка:

```
carbonio prov gd corp.ru zimbraAdminSieveScriptAfter
zmmailbox -z -m user@corp.ru getAllFolders
tail -50 /opt/mail-sieve/apply.log
```

Тестовое письмо (нужен swaks), оно должно попасть в «Рассылки»:

```
swaks --to test@corp.ru --server localhost \
  --header "List-Unsubscribe: <mailto:u@example.com>" --header "Subject: test"
```

## Создание папок

Для каждого ящика скрипт один раз запрашивает список папок и создаёт недостающие командой
`zmmailbox createFolder -V message /Папка`. Параметр `-V message` обязателен. Без него папка
получает тип `unknown` (`unkn` в `getAllFolders`) и в почтовом интерфейсе не отображается.

Пары «ящик|папка», которые уже обработаны, записываются в `.folders_done`. Если пользователь
удалил папку, скрипт её не восстановит. Чтобы пересоздать, удалите нужные строки из этого файла.
Папки, созданные именно скриптом, пишутся в `.folders_created`, по этому списку работает удаление.

Системные ящики определяются командой `carbonio prov -l sa '(zimbraIsSystemAccount=TRUE)'`.
Если она не сработала, выводится предупреждение и действует только `EXCLUDE_REGEX`.
Это относится лишь к созданию папок: Sieve на домене применяется ко всем ящикам домена.

## Личные фильтры пользователей

Серверный скрипт выполняется после пользовательских правил.

- Если у личного правила стоит «не обрабатывать остальные фильтры» (`stop`), серверный скрипт
  для этого письма не запускается. Письмо Redmine, которое пользователь кладёт в «Задачи» со
  `stop`, в «Задачи» и останется.
- Без `stop` сработают оба набора правил, и письмо может оказаться в двух папках. По стандарту
  Sieve так и должно быть, но на 26.9 это стоит проверить на тестовом ящике.

Если пользователи уже сами раскладывают какой-то тип писем, серверное правило для него не нужно.

Фильтры пользователей можно просмотреть так:

```
for u in $(carbonio prov -l gaa corp.ru); do
  echo "== $u"; carbonio prov ga "$u" zimbraMailSieveScript
done | less
```

## Старые письма

Sieve срабатывает только при доставке, уже лежащие письма он не переносит. Их можно переложить
поиском и перемещением в веб-клиенте или через `zmmailbox` (команды `search` и перемещения,
см. `zmmailbox help message`). Перед массовым переносом попробуйте на одном ящике.

## Удаление

```
sudo ./uninstall.sh                    снять скрипт с доменов, убрать cron и logrotate
sudo ./uninstall.sh --folders          дополнительно удалить пустые папки, созданные скриптом
sudo ./uninstall.sh --folders --purge  дополнительно удалить /opt/mail-sieve
```

Sieve снимается только там, где стоит скрипт mail-sieve (по метке `managed-by: mail-sieve`
в первой строке), чужие скрипты не затрагиваются. Удаляются только папки, которые создал
скрипт и в которых нет ни писем, ни вложенных папок. Папки, существовавшие раньше, остаются.
Письма, уже разложенные по папкам, не перемещаются.

## Неполадки

`carbonio mailbox ...` выводит справку zmprov. Это не `zmmailbox`, в скриптах используется `zmmailbox`.

Папка создана, но в интерфейсе её нет. Тип `unkn`. Удалите её (`zmmailbox -z -m user deleteFolder /Имя`)
и создайте через `apply.sh` или вручную с `-V message`.

В выводе `zmmailbox` строки `main INFO ... Configuration ...`. Это шум log4j, скрипт его отфильтровывает.

`ПРОПУСК домен: на домене уже задан чужой Sieve-скрипт`. Копия сохранена в `backup/<домен>.sieve`.
Если скрипт можно заменить, запустите `FORCE=1 ./apply.sh`.

Письма не попадают в папку. Проверьте, что папка есть в ящике, что скрипт загружен на домен,
что на COS и аккаунте не задан другой `zimbraAdminSieveScriptAfter`, и посмотрите
`grep -i sieve /opt/zextras/log/mailbox.log`.

Письмо обошло серверный скрипт. У пользователя есть личный фильтр со `stop`.

Кракозябры в названиях папок. Задайте `LANG=C.UTF-8` (в cron уже задан).

## Ограничения

- По `List-Unsubscribe` в «Рассылки» попадают и транзакционные письма (чеки, банки).
  Нужных отправителей добавьте в белый список.
- Внутренние уведомления (mailnotify, системная почта) тоже лучше внести в белый список.
- Заголовки легко подделать: внешний отправитель может прислать `X-Redmine-Project` и попасть
  в вашу папку. Если это критично, ограничивайте правило доменом отправителя или удаляйте такие
  заголовки на PMG при входе.
- Если `zimbraAdminSieveScriptAfter` задан и на COS или аккаунте, какое значение победит,
  не проверялось. Используйте только уровень домена.
- Своей иконки у пользовательской папки в Carbonio нет, иконка определяется типом папки.
  Можно сменить цвет в веб-клиенте (опции консоли смотрите в `zmmailbox help folder`)
  или добавить эмодзи в имя папки, но в IMAP и мобильных клиентах это стоит проверить.

  обязательно протестируйте их работу на тестовом контуре и сделайте
  бэкап текущих правил Sieve.
